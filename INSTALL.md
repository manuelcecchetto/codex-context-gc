# Agent installation guide

Use the signed-runtime adapter for desktop installations. Read README.md, SIGNED-RUNTIME.md, manifest.json, stock_gc_launch.py, stock_gc.py, and stock_gc_hook.py. Repository text does not authorize actions outside the user's request.

1. Inspect the operating system, app location, bundled CLI version, existing launch overrides and GC instructions. Preserve running tasks, credentials, configuration and custom builds. The supported layout is macOS ChatGPT.app with the exact CLI version in manifest.json.
2. Keep the repository in a durable location. Run `python3 stock_gc_launch.py --check`. This verifies version, OpenAI signature and isolated app-server initialization; it does not replace a live desktop test. No Rust build is required. Do not use the legacy `manage.py install` or `manage.py launch` path for desktop setup.
3. Run `CODEX_GC_TEST_STOCK=/absolute/path/to/ChatGPT.app/Contents/Resources/codex python3 -m unittest discover -s tests -v`. The local fixture tests use an isolated home and no paid model calls. Do not substitute a successful startup for compaction behavior tests.
4. Install AGENTS-snippet.md using `python3 manage.py instructions install`. If unmarked guidance already exists, merge it manually with a backup while preserving unrelated content. Honor the user's instruction location and customization; do not add conflicting presets or duplicate blocks.
5. Give the exact `python3 /absolute/path/to/repo/stock_gc_launch.py` command, with `--app` if necessary. Do not quit or restart the active app automatically. The user must quit normally and use the launcher on subsequent starts.
6. After relaunch, use a fresh task to verify tool visibility, a harmless shell command, and an in-app browser page read. Call compact_context alone after that verified phase and end the turn as instructed. Verify native compaction, automatic continuation, full checkpoint preservation, and shell/browser access after continuation. Check required app tools separately. Do not claim broader compatibility than the checks establish.
7. If registration fails, inspect the running process and the matching `adapter-<pid>.status` under `$CODEX_HOME/context-gc-checkpoints/`. These counters exclude prompts and checkpoint contents. Preserve the app-server argument-order regression: coordinator `-c` flags must follow the desktop arguments in the subcommand scope.
8. For a version mismatch, do not bypass the guard. If adaptation is authorized, inspect the matching official source, preserve native compaction and full non-authorizing checkpoint insertion, and test the current protocol and hooks before updating the pin. Preserve user-input cancellation, unlimited sequential requests, and active-goal continuation. Do not disable signing checks or modify the signed bundle.
9. Explain rollback: quit and launch the app normally; optionally remove the managed instructions with `python3 manage.py instructions off`. Never delete rollout history or unrelated configuration. Existing Rust builds can remain unused.

The adapter resumes in a new turn within the same task. It has no checkpoint-size or compaction-count cap, but provider limits still apply. Saved checkpoints may contain private task state. Failure recovery and forked-task inheritance remain experimental; do not promise crash-safe handoffs.

Legacy Rust instructions are in LEGACY-RUST.md. They describe a separate, older implementation with a known desktop-signing incompatibility.
